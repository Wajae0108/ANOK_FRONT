AI 기반 사내 업무 지식·의사결정 관리 시스템
1. Project 개요 및 필요성

기업에서는 회의, 메신저, 보고서, 프로젝트 문서 등을 통해 매일 많은 업무 정보와 의사결정이 발생한다. 그러나 시간이 지나면서 누가 어떤 결정을 내렸는지, 왜 그렇게 결정했는지, 이후 어떤 업무가 누구에게 배정되었는지​를 다시 확인하기 어려운 문제가 발생한다.

특히 프로젝트가 장기간 진행되거나 담당자가 변경될 경우, 과거 의사결정의 배경과 업무 맥락이 충분히 전달되지 않아 같은 논의를 반복하거나 잘못된 판단을 내릴 가능성이 있다.

본 프로젝트는 이러한 문제를 해결하기 위해 회의 보고서와 업무 토의 내용을 AI가 분석하여 다음과 같은 정보를 자동으로 구조화하고 관리하는 사내 AI 시스템을 개발하는 것을 목표로 한다.

주요 논의 내용
최종 의사결정
결정 이유 및 근거
관련 프로젝트 및 문서
의사결정 참여자
담당자 및 후속 업무(Action Item)
업무 진행 상태

축적된 정보는 기존 프로젝트 데이터와 연결하여 하나의 사내 업무 지식 데이터베이스로 관리한다. 사용자는 자연어로 AI에게 질문하여 과거 프로젝트의 결정 과정과 업무 정보를 검색할 수 있다.

예를 들어 사용자가
“지난달 로그인 방식 변경 이유가 뭐였어?”
라고 질문하면 AI가 관련 회의와 문서를 찾아 결정 내용, 결정 이유, 참여자, 관련 자료 등을 함께 제공하는 방식이다.

궁극적으로는 회사의 내부 데이터를 AI가 이해하고 실제 업무에 활용할 수 있는 기업 맞춤형 AI 업무 시스템을 구축하는 것이 목적이다.

2. 국내·외 관련 프로그램 현황

현재에도 기업 내부 데이터를 AI와 연결하려는 다양한 서비스가 등장하고 있다.

국내

NAVER WORKS AI Studio

NAVER WORKS의 게시판, 메시지, 드라이브 등에 축적된 사내 데이터를 AI가 탐색하여 회사 내부 정보를 기반으로 질문에 답할 수 있는 기업용 AI 서비스를 제공하고 있다.

NAVER WORKS CLOVA Note

회의 내용을 기록하고 AI가 주요 내용을 요약하며 다음 할 일을 추천한다. 2026년에는 회의 참석자를 자동으로 구분하는 화자 자동 식별 기능도 제공하고 있다.

해외

Notion AI

Notion 내부 문서뿐만 아니라 Slack, Google Drive, Jira 등의 업무 데이터를 연결하여 AI가 회사 정보를 검색하고 질문에 답할 수 있는 Enterprise Search 기능을 제공하고 있다. 회의 내용을 기록·요약하는 AI Meeting Notes 기능도 제공한다.

Atlassian Rovo

Jira, Confluence, Google Drive, Slack 등 여러 업무 시스템의 데이터를 연결하고 회사 내부 지식을 자연어로 검색할 수 있도록 지원한다. 프로젝트, 사람, 업무 정보를 연결해 조직의 업무 맥락을 파악하는 기능을 제공한다.

Slack Enterprise Search

Slack 대화뿐만 아니라 Google Drive, GitHub 등 기업에서 사용하는 외부 업무 시스템의 데이터를 통합 검색하고 자연어 질문을 통해 필요한 정보를 탐색할 수 있도록 지원한다.

기존 서비스와 본 프로젝트의 차별점

기존 서비스가 주로 문서 검색, 회의 요약, 기업 데이터 검색​에 집중한다면 본 프로젝트는 단순한 문서 검색을 넘어 업무에서 발생한 의사결정 자체를 하나의 데이터로 관리하는 것을 핵심으로 한다.

예를 들어 하나의 의사결정을 다음과 같이 구조화한다.

결정 사항 → 결정 이유 → 관련 회의 → 관련 프로젝트 → 참여자 → 담당자 → 후속 업무 → 진행 결과

이를 통해 단순히 “관련 문서를 찾는 AI”가 아니라 회사의 의사결정 과정과 업무 흐름을 기억하는 AI 시스템을 구현하고자 한다.

3. 개발 목표 및 범위
1단계 : 업무 데이터 수집

회의록, 회의 보고서, 프로젝트 문서 및 업무 토의 내용을 시스템에 등록한다.

초기 버전에서는 텍스트 및 문서 입력을 중심으로 개발하고 이후 음성 회의 데이터까지 확장한다.

2단계 : AI 기반 업무 정보 분석

LLM을 이용하여 입력된 업무 데이터에서 다음 정보를 자동 추출한다.

프로젝트
회의 주제
주요 논의 내용
결정 사항
결정 이유
관련 인원
담당자
후속 업무
중요 키워드
3단계 : 프로젝트 및 업무 정보 연결

추출된 정보를 기존 프로젝트 데이터와 연결한다.

예를 들어,

프로젝트 A

→ 9월 10일 로그인 기능 회의
→ OAuth 방식 도입 결정
→ 보안성과 확장성 때문에 선택
→ 담당자 이규찬
→ 로그인 API 개발 업무 생성

과 같이 프로젝트의 진행 과정과 의사결정을 연결한다.

4단계 : AI 기반 사내 지식 검색

사용자가 자연어로 질문하면 사내 데이터를 검색하고 관련 정보를 기반으로 답변한다.

예시)

“OAuth를 사용하기로 결정한 이유가 뭐야?”

“로그인 API 담당자가 누구야?”

“지난달 프로젝트 A에서 결정된 내용 정리해줘.”

“아직 처리되지 않은 후속 업무가 뭐가 있어?”

5. 시스템 구성 및 사용할 기술
Front-End

React + TypeScript

사용자 Dashboard, 프로젝트 화면, AI 검색 인터페이스, 업무 관리 페이지 등을 개발한다.

Back-End

FastAPI (Python)

AI 분석 API, 문서 처리, RAG 검색 및 LLM 연동 기능을 담당한다.

필요할 경우 일반적인 사용자/프로젝트 관리 API는 Spring Boot로 분리하여 구성할 수 있다.

Database

PostgreSQL

사용자, 프로젝트, 회의, 의사결정, 업무 등의 정형 데이터를 저장한다.

주요 데이터 구조 예시:

User

Project

Meeting

Decision

DecisionReason

ActionItem

Document

Vector Database

PostgreSQL + pgvector

문서 및 회의 내용을 임베딩하여 의미 기반 검색이 가능하도록 구성한다.

AI / LLM

OpenAI API 또는 로컬 LLM을 활용하여

회의 내용 요약
핵심 정보 추출
의사결정 분석
Action Item 생성
사내 데이터 질의응답

기능을 구현한다.

RAG

사내 데이터를 임베딩하여 Vector DB에 저장하고 사용자의 질문과 연관성이 높은 내부 데이터를 검색한 뒤 LLM에 Context로 전달한다.

사용자 질문

→ 질문 Embedding

→ Vector DB 검색

→ 관련 회사 자료 추출

→ LLM 분석

→ 근거가 포함된 답변 제공

6. 구현 결과 및 진행 현황

현재 프로젝트 아이디어 및 핵심 기능을 정의한 단계이며 다음과 같은 시스템 방향을 설정하였다.

AI 기반 사내 업무 지식 관리
회의 및 업무 내용 AI 분석
의사결정 및 결정 이유 추출
관련 프로젝트 자동 연결
후속 업무 및 담당자 관리
기업 내부 데이터를 활용한 AI 질의응답

다음 단계에서는 실제 회사 업무 상황을 가정한 테스트 데이터를 구축하고 AI가 회의 내용에서 의사결정과 Action Item을 정확하게 추출할 수 있는지 검증한다.

최종 구현 목표

프로젝트 완료 시 다음 시나리오를 실제 프로그램에서 시연하는 것을 목표로 한다.

① 회의록 입력

↓

② AI가 회의 내용 분석

↓

③ 결정사항·결정 이유·담당자·업무 자동 추출

↓

④ 기존 프로젝트와 자동 연결

↓

⑤ 담당자 Dashboard에 업무 생성

↓

⑥ 이후 사용자가 AI에게 과거 업무 내용 질문

↓

⑦ 관련 회의·문서·결정을 근거로 답변 제공

이를 통해 회사 내부에서 발생하는 회의 → 결정 → 업무 → 결과의 전체 흐름을 하나의 시스템에서 확인할 수 있도록 한다.

기업 맞춤형 AI 구축

회사마다 사용하는 용어, 업무 프로세스, 조직 구조 및 내부 문서가 다르기 때문에 각 기업의 데이터를 기반으로 해당 기업에 특화된 AI 환경을 구축한다.

최종적으로는 사용자가

“현재 프로젝트에서 가장 큰 문제점이 뭐야?”

“이 기능은 왜 이렇게 개발됐어?”

“과거에 비슷한 문제가 있었어?”

“이번 프로젝트에서 지연되고 있는 업무를 찾아줘.”

와 같이 질문하면 회사 내부 정보를 분석하여 답변하는 기업 전용 AI 업무 어시스턴트로 발전시키는 것을 목표로 한다.
